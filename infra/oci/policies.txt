# MediFlow - Políticas IAM para OCI (N2-02)
#
# Grupos reales:
# - mediflow-developers (grupo de desarrollo) → solo escribe en mediflow-dev
# - Administrators (grupo admin) → todo
#
# Dynamic groups:
# - mediflow-vm → solo escribe en mediflow-prod
#
# Objetivo:
# - Los devs solo pueden escribir en el bucket de desarrollo (mediflow-dev).
# - La VM (dynamic group) solo puede escribir en el bucket de producción (mediflow-prod).
# - Ningún dev puede escribir en el bucket de producción.

# Administradores: pueden gestionar todo el compartment
Allow group Administrators to manage all-resources in compartment mediflow

# Devs: solo pueden gestionar objects en el bucket de desarrollo
Allow group Default/mediflow-developers to manage object-family in compartment mediflow where target.bucket.name = 'mediflow-dev'


# Devs: otros permisos (database, secrets, instancias)
Allow group Default/mediflow-developers to use autonomous-databases in compartment mediflow
Allow group Default/mediflow-developers to read secret-family in compartment mediflow
Allow group Default/mediflow-developers to read instances in compartment mediflow

# VM (dynamic group): solo puede gestionar objects en el bucket de producción
Allow dynamic-group mediflow-vm to manage objects in compartment mediflow where target.bucket.name = 'mediflow-prod'

# VM: otros permisos
Allow dynamic-group mediflow-vm to read secret-family in compartment mediflow
Allow dynamic-group mediflow-vm to use ons-topics in compartment mediflow

# Dynamic group para la VM (crear con OCI CLI)
# Regla: Any {instance.compartment.id = '<OCID del compartment mediflow>'}
